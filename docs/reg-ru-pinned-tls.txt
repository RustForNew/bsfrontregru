XHTTP-SETUP: REG.RU FRONTEND + BARE XRAY EXIT
Пошаговая установка с pinned TLS

ВАЖНО: это проверенный ручной runbook. Для автоматизированного запуска с одного
Linux/WSL-компьютера используйте режим pc из README. Не смешивайте способы:
pc требует уже активный clean UFW и не выполняет раздел 7, который включает и
меняет defaults UFW. Подготовка сайта, DNS, TLS и измерение FRONT_EGRESS_IP ниже
остаются актуальны.

Команды публикации ниже фиксируют проверенное состояние 0.4.0. Для текущего
пользовательского запуска используйте INSTRUCTION.txt из Release 0.4.1.

Схема после настройки:

  клиент -- VLESS Encryption + XHTTP packet-up + TLS:443 --> сайт REG.RU
  Apache REG.RU -- HTTP/XHTTP --> bare Xray exit:8083 --> интернет

В трафике участвуют два узла: сайт REG.RU и зарубежный exit. Российский bridge
нужен только для запуска SFTP-настройки. На REG.RU не устанавливаются Xray,
Docker или Remnawave. Домен exit в клиентской ссылке не используется.

Инструкция рассчитана на:

  - новый сайт в ISPmanager REG.RU;
  - чистый Ubuntu/Debian exit с systemd, root и UFW;
  - Linux/WSL с обычным IP для управления exit;
  - Linux-сервер с российским IP для обращения к REG.RU;
  - опубликованный GitHub Release xhttp-setup v0.4.0.

Не используйте раздел UFW на сервере с Docker, собственными nftables/iptables
или другими сервисами. Для такого сервера правила нужно объединять вручную.


0. Один раз опубликовать xhttp-setup в GitHub
================================================

Создать пустой репозиторий GitHub. Открыть Settings -> General -> Releases и
включить immutable releases. Далее на компьютере владельца открыть корень
проекта xhttp-setup и выполнить из Git Bash или WSL:

  test -z "$(git status --porcelain)" || {
    echo 'Есть незакоммиченные файлы'; exit 1;
  }
  test "$(git branch --show-current)" = main || {
    echo 'Текущая ветка не main'; exit 1;
  }

  XH_PUBLISH_URL='https://github.com/RustForNew/bsfrontregru.git'
  if git remote get-url publish >/dev/null 2>&1; then
    test "$(git remote get-url publish)" = "$XH_PUBLISH_URL" || {
      echo 'Remote publish указывает на другой репозиторий'; exit 1;
    }
  else
    git remote add publish "$XH_PUBLISH_URL"
  fi

  git push -u publish main
  git tag -a v0.4.0 -m 'xhttp-setup v0.4.0'
  git push publish v0.4.0

Открыть GitHub -> Actions -> Release. Дождаться зелёного результата. В Releases
должны появиться шесть файлов:

  xhttp-setup-0.4.0.pyz
  xhttp-setup-0.4.0.pyz.sha256
  xhttp-setup-0.4.0-windows-wsl.zip
  xhttp-setup-0.4.0-windows-wsl.zip.sha256
  home-pc-linux-windows.txt
  reg-ru-ispmanager-setup.txt

На странице release должна быть отметка Immutable. Если её нет, не
устанавливать этот release: включить immutable releases и выпустить новый
тег.

После публикации подключиться по SSH к exit и один раз выполнить там следующий
блок. Затем один раз выполнить его на российском bridge. Заменить
RustForNew/bsfrontregru:

  (
    set -Eeuo pipefail

    XH_REPO='RustForNew/bsfrontregru'
    XH_TAG='v0.4.0'
    XH_ASSET='xhttp-setup-0.4.0.pyz'
    XH_TMP="$(mktemp -d)"
    trap 'rm -rf -- "$XH_TMP"' EXIT
    XH_BASE="https://github.com/$XH_REPO/releases/download/$XH_TAG"

    command -v curl >/dev/null
    command -v python3 >/dev/null
    command -v sha256sum >/dev/null
    python3 -c 'import sys; sys.version_info >= (3, 10) or sys.exit("Python 3.10+ required")'

    curl --fail --silent --show-error --location \
      --proto '=https' --proto-redir '=https' --retry 3 \
      --output "$XH_TMP/$XH_ASSET" "$XH_BASE/$XH_ASSET"

    curl --fail --silent --show-error --location \
      --proto '=https' --proto-redir '=https' --retry 3 \
      --output "$XH_TMP/$XH_ASSET.sha256" "$XH_BASE/$XH_ASSET.sha256"

    XH_EXPECTED="$(tr -d '\r\n' < "$XH_TMP/$XH_ASSET.sha256")"
    case "$XH_EXPECTED" in
      ''|*[!0-9a-fA-F]*) echo 'Некорректный SHA-256'; exit 1 ;;
    esac
    test "${#XH_EXPECTED}" -eq 64

    XH_ACTUAL="$(sha256sum "$XH_TMP/$XH_ASSET" | awk '{print $1}')"
    test "${XH_ACTUAL,,}" = "${XH_EXPECTED,,}" || {
      echo 'SHA-256 не совпал'; exit 1;
    }

    python3 "$XH_TMP/$XH_ASSET" --version
    sudo install -m 0755 "$XH_TMP/$XH_ASSET" \
      /usr/local/bin/.xhttp-setup.new
    sudo mv -f /usr/local/bin/.xhttp-setup.new /usr/local/bin/xhttp-setup
    /usr/local/bin/xhttp-setup --version
  )

Ожидаемый вывод версии:

  xhttp-setup 0.4.0


1. Записать исходные данные
===========================

До настройки заполнить список:

  FRONT_DOMAIN          полный домен сайта, например front.example.org
  SITE_IP               IPv4, назначенный сайту в ISPmanager
  DNS_IPV4              IPv4 единственной DNS A-записи
  CLIENT_CONNECT_IP     IPv4 подключения клиента и адрес в VLESS URI
  FRONT_EGRESS_IP       будет измерен в разделе 5
  TLS_PIN               будет получен в разделе 4
  EXIT_IP               публичный IPv4 зарубежного VPS
  EXIT_EGRESS_IP        исходящий IPv4 зарубежного VPS
  EXIT_SSH_PORT         фактический порт sshd, обычно 22
  BACKEND_PORT          8083
  SFTP_HOST             hosting-node вида vipNNN.hosting.reg.ru
  SFTP_PORT             22
  SFTP_USER             пользователь хостинга
  DOCROOT               корень сайта из ISPmanager
  SFTP_HOSTKEY_SHA256   fingerprint вида SHA256:...
  BRIDGE_IP             IPv4 российского Linux-сервера
  BRIDGE_SSH_PORT       фактический SSH-порт bridge
  EXIT_HOSTKEY_SHA256   SSH fingerprint exit из консоли VPS
  BRIDGE_HOSTKEY_SHA256 SSH fingerprint bridge из консоли VPS

Надпись «2222» в названии VPS не означает, что sshd слушает порт 2222. Порт
проверяется командой на самом VPS:

  sudo /usr/sbin/sshd -T | awk '$1 == "port" { print $2 }'


2. Создать сайт в ISPmanager
============================

Если REG.RU в окне «Подключение домена» пишет «Неверное имя домена», закрыть это
окно. Открыть ISPmanager с российского IP -> Сайты -> Добавить сайт.

Заполнить:

  Имя:                         FRONT_DOMAIN
  Псевдонимы:                  пусто
  Корневая директория:         предложенная для FRONT_DOMAIN
  Источник IP-адреса:          получить автоматически
  E-mail администратора:       адрес владельца
  Кодировка:                   не указывать
  Индексная страница:          index.php index.html
  Редирект домена:             не включён
  Автоподдомены:               отключено

SSL:

  Защищённое соединение SSL:   включено
  SSL-порт:                    443
  SSL-сертификат:              Новый самоподписанный
  HSTS:                        выключено
  HTTP -> HTTPS:               выключено

Оставить включёнными:

  PHP
  Режим работы PHP: FastCGI (Apache)
  Журнал ошибок
  Период ротации: ежедневно
  Хранить архивов: 3

Выключить:

  SSI
  CGI-скрипты
  Python
  Тестовый домен для WordPress
  php.ini для домена
  Журнал запросов
  Настроить сжатие
  Настроить кеширование
  Генератор отчётов

Поле «Расширения файлов для кеширования» не менять. При выключенном кешировании
оно не используется. Версия PHP не влияет на схему; PHP-файлы не запускаются.
Переключатель FastCGI (Apache) нужен, чтобы nginx передавал неизвестный XHTTP path
в Apache, где выполняется .htaccess.

Нажать «Создать». Затем открыть карточку сайта и записать:

  - назначенный IPv4 как SITE_IP;
  - точную корневую директорию как DOCROOT;
  - выбранный сертификат сайта.

Не составлять DOCROOT по шаблону. Скопировать его из карточки сайта.


3. Создать DNS-запись frontend
==============================

В проверенном новом REG.RU-сайте SITE_IP, DNS_IPV4 и CLIENT_CONNECT_IP совпали:

  DNS_IPV4 = SITE_IP
  CLIENT_CONNECT_IP = SITE_IP

Создать в Cloudflare одну запись:

  Type:          A
  Name:          нужный поддомен
  Content:       DNS_IPV4
  Proxy status:  DNS only, серое облако
  TTL:           Auto

Для FRONT_DOMAIN удалить AAAA и CNAME. Cloudflare proxy не включать. Запись
exit.example.org не нужна для XHTTP и не попадёт в клиентскую ссылку.

Проверить с Linux/WSL. SITE_IP показан как default для двух ролей; если DNS или
адрес подключения фактически другой, ввести его. Эту shell-сессию
не закрывать до конца раздела 5:

  set -Eeuo pipefail
  read -r -p 'FRONT_DOMAIN: ' FRONT_DOMAIN
  read -r -p 'SITE_IP из ISPmanager: ' SITE_IP
  read -r -p "DNS_IPV4 [$SITE_IP]: " DNS_IPV4
  DNS_IPV4="${DNS_IPV4:-$SITE_IP}"
  read -r -p "CLIENT_CONNECT_IP [$SITE_IP]: " CLIENT_CONNECT_IP
  CLIENT_CONNECT_IP="${CLIENT_CONNECT_IP:-$SITE_IP}"

  sudo apt-get update
  sudo apt-get install -y curl dnsutils openssl python3

  mapfile -t XH_A < <(dig +short A "$FRONT_DOMAIN")
  test "${#XH_A[@]}" -eq 1
  test "${XH_A[0]}" = "$DNS_IPV4"
  XH_AAAA="$(dig +short AAAA "$FRONT_DOMAIN")"
  test -z "$XH_AAAA"
  echo 'DNS: OK'

Эти команды требуют ровно одну A-запись DNS_IPV4 и отсутствие AAAA.


4. Проверить HTTPS-vhost и получить TLS_PIN
===========================================

Открыть сайт на редактирование. Проверить:

  SSL включён
  порт 443
  выбран сертификат FRONT_DOMAIN
  HSTS выключен
  HTTP -> HTTPS выключен

Скачать HTTP- и HTTPS-страницы с точным IP, Host и SNI:

  XH_HTTP_BODY="$(mktemp)"
  XH_HTTPS_BODY="$(mktemp)"
  trap 'rm -f -- "$XH_HTTP_BODY" "$XH_HTTPS_BODY"' EXIT

  XH_HTTP_STATUS="$(
    curl --fail-with-body --silent --show-error --noproxy '*' \
      --connect-timeout 5 --max-time 20 \
      --resolve "$FRONT_DOMAIN:80:$CLIENT_CONNECT_IP" \
      "http://$FRONT_DOMAIN/" \
      --output "$XH_HTTP_BODY" --write-out '%{http_code}'
  )"

  XH_HTTPS_STATUS="$(
    curl --insecure --fail-with-body --silent --show-error --noproxy '*' \
      --connect-timeout 5 --max-time 20 \
      --resolve "$FRONT_DOMAIN:443:$CLIENT_CONNECT_IP" \
      "https://$FRONT_DOMAIN/" \
      --output "$XH_HTTPS_BODY" --write-out '%{http_code}'
  )"

  test "$XH_HTTP_STATUS" = '200'
  test "$XH_HTTPS_STATUS" = '200'
  test -s "$XH_HTTP_BODY"
  test -s "$XH_HTTPS_BODY"
  cmp -s "$XH_HTTP_BODY" "$XH_HTTPS_BODY"
  echo 'HTTP/HTTPS vhost: OK'

Если проверка остановилась, по 80 и 443 открываются разные сайты или ошибочный
ответ. Исправить IP/SSL-vhost в ISPmanager. Pin с неправильного vhost не
использовать.

Получить SHA-256 полного DER leaf-сертификата:

  XH_CERT_DER="$(mktemp)"
  trap 'rm -f -- "$XH_HTTP_BODY" "$XH_HTTPS_BODY" "$XH_CERT_DER"' EXIT

  if ! (
    set -o pipefail
    timeout 20 openssl s_client \
      -connect "$CLIENT_CONNECT_IP:443" \
      -servername "$FRONT_DOMAIN" \
      </dev/null 2>/dev/null \
    | openssl x509 -outform DER > "$XH_CERT_DER"
  ); then
    echo 'Не удалось получить leaf-сертификат'
    exit 1
  fi

  test -s "$XH_CERT_DER"
  TLS_PIN="$(sha256sum "$XH_CERT_DER" | awk '{print $1}')"
  [[ "$TLS_PIN" =~ ^[0-9a-f]{64}$ ]]
  rm -f -- "$XH_CERT_DER"
  rm -f -- "$XH_HTTP_BODY" "$XH_HTTPS_BODY"
  trap - EXIT
  printf '%s\n' "$TLS_PIN"

Записать результат как TLS_PIN. Параметр -servername обязателен. Не использовать
hash из секции «without SNI», fingerprint CA или SPKI.

В этом режиме публичный Let's Encrypt не нужен. Сертификат и SSL-vhost на 443
обязательны. Клиент будет принимать только leaf с TLS_PIN. allowInsecure в ссылку
не добавляется. После замены сертификата нужно получить новый TLS_PIN и заново
выпустить ссылку.


5. Измерить FRONT_EGRESS_IP
===========================

FRONT_EGRESS_IP — адрес, с которого Apache REG.RU подключается к exit. Он может
не совпасть с CLIENT_CONNECT_IP или FTP IP. Измерение выполняется до установки
Xray.

В той же Linux/WSL shell создать случайный path пробы и вывести готовый
.htaccess. По запросу ввести EXIT_IP:

  read -r -p 'EXIT_IP: ' EXIT_IP
  python3 -c 'import ipaddress,sys; v=ipaddress.ip_address(sys.argv[1]); (v.version == 4 and v.is_global) or sys.exit("EXIT_IP не публичный IPv4")' \
    "$EXIT_IP"
  XH_PROBE_PORT='18083'
  XH_PROBE_TOKEN="xhttp-egress-$(openssl rand -hex 8)"
  printf 'RewriteEngine On\nRewriteRule ^%s$ http://%s:%s/ [P,L]\n' \
    "$XH_PROBE_TOKEN" "$EXIT_IP" "$XH_PROBE_PORT"

На exit открыть SSH-сессию с обычного IP. Установить tcpdump и
убедиться, что пробный порт свободен:

  (
    set -Eeuo pipefail
    sudo apt-get update
    sudo apt-get install -y python3 tcpdump
    XH_PROBE_PORT='18083'
    if sudo ss -H -lnt "sport = :$XH_PROBE_PORT" | grep . >/dev/null; then
      echo 'Порт 18083 занят'
      exit 1
    fi
  )

В ISPmanager открыть Файлы -> DOCROOT. На новом сайте .htaccess должен
отсутствовать. Если он уже есть, остановиться: этот линейный порядок рассчитан
на новый сайт и не должен перезаписывать существующие правила.

Создать в DOCROOT временный файл .htaccess и вставить в него ровно две
строки, которые напечатала команда выше.

На exit запустить весь блок ниже. Он ждёт 12 SYN; пока он работает,
выполнить следующий блок с Linux/WSL:

  (
    set -Eeuo pipefail
    XH_PROBE_PORT='18083'
    XH_CAPTURE="$(mktemp)"
    trap 'rm -f -- "$XH_CAPTURE"' EXIT
    sudo timeout 240 tcpdump -nn -l -i any -c 12 \
      "tcp dst port $XH_PROBE_PORT and (tcp[tcpflags] & tcp-syn != 0)" \
      | tee "$XH_CAPTURE"

    XH_SYN_COUNT="$(awk '{for (i=1; i<=NF; i++) if ($i == ">") c++} END {print c+0}' \
      "$XH_CAPTURE")"
    test "$XH_SYN_COUNT" -eq 12
    mapfile -t XH_SOURCES < <(
      awk '{for (i=1; i<=NF; i++) if ($i == ">") {s=$(i-1); sub(/\.[0-9]+$/, "", s); print s}}' \
        "$XH_CAPTURE" | sort -u
    )
    test "${#XH_SOURCES[@]}" -eq 1
    FRONT_EGRESS_IP="${XH_SOURCES[0]}"
    python3 -c 'import ipaddress,sys; v=ipaddress.ip_address(sys.argv[1]); (v.version == 4 and v.is_global) or sys.exit("FRONT_EGRESS_IP не публичный IPv4")' \
      "$FRONT_EGRESS_IP"
    printf 'FRONT_EGRESS_IP=%s\n' "$FRONT_EGRESS_IP"
  )

Пока capture работает, с Linux/WSL выполнить:

  for XH_N in $(seq 1 12); do
    curl --insecure --silent --show-error --noproxy '*' \
      --connect-timeout 5 --max-time 10 \
      --resolve "$FRONT_DOMAIN:443:$CLIENT_CONNECT_IP" \
      "https://$FRONT_DOMAIN/$XH_PROBE_TOKEN" \
      --output /dev/null || true
    sleep 5
  done

Записать напечатанный FRONT_EGRESS_IP. Если первая проверка остановилась, получено
меньше 12 SYN. Если остановилась вторая, SYN пришли от нескольких IPv4 и текущая
версия xhttp-setup с одним /32 для этого хостинга не подходит.

Если tcpdump не увидел пакетов:

  1. Проверить, что FRONT_DOMAIN/path ответил не nginx 404.
  2. Проверить PHP -> FastCGI (Apache).
  3. Если у VPS есть внешний cloud firewall, временно разрешить TCP 18083,
     повторить capture, удалить это правило и проверить, что порт снова
     закрыт в cloud firewall. Сервис на 18083 не запускать.

После измерения удалить временный .htaccess в ISPmanager. В разделе 6 команда
`ls -la` должна подтвердить, что файла больше нет. Не переходить к установке,
пока probe-правило остаётся в DOCROOT.


6. Проверить SFTP REG.RU
========================

SFTP_HOST — hosting-node из адреса ISPmanager, например
vipNNN.hosting.reg.ru. Не использовать CLIENT_CONNECT_IP или FTP IP.
SFTP_PORT — 22.

На российском bridge установить инструменты:

  sudo apt-get update
  sudo apt-get install -y ca-certificates curl openssl openssh-client python3

Получить ожидаемый SFTP_HOSTKEY_SHA256 через панель или поддержку REG.RU. Затем
ввести данные по запросам и проверить, что hosting-node предъявляет этот ключ:

  set -Eeuo pipefail
  read -r -p 'SFTP_HOST: ' SFTP_HOST
  read -r -p 'SFTP_USER: ' SFTP_USER
  read -r -p 'SFTP_HOSTKEY_SHA256: ' SFTP_HOSTKEY_SHA256
  SFTP_PORT='22'
  XH_EXPECTED_FP="${SFTP_HOSTKEY_SHA256%=}"
  [[ "$XH_EXPECTED_FP" =~ ^SHA256:[A-Za-z0-9+/]{43}$ ]]

  XH_KEYSCAN="$(mktemp)"
  XH_ONE_KEY="$(mktemp)"
  XH_PINNED_KEY="$(mktemp)"
  trap 'rm -f -- "$XH_KEYSCAN" "$XH_ONE_KEY" "$XH_PINNED_KEY"' EXIT
  chmod 600 "$XH_KEYSCAN" "$XH_ONE_KEY" "$XH_PINNED_KEY"

  ssh-keyscan -T 10 -p "$SFTP_PORT" -t ed25519,ecdsa,rsa "$SFTP_HOST" \
    > "$XH_KEYSCAN"
  test -s "$XH_KEYSCAN"
  : > "$XH_PINNED_KEY"

  while IFS= read -r XH_KEY_LINE; do
    printf '%s\n' "$XH_KEY_LINE" > "$XH_ONE_KEY"
    XH_KEY_FP="$(
      ssh-keygen -E sha256 -lf "$XH_ONE_KEY" | awk '{print $2}'
    )"
    XH_KEY_FP="${XH_KEY_FP%=}"
    if test "$XH_KEY_FP" = "$XH_EXPECTED_FP"; then
      printf '%s\n' "$XH_KEY_LINE" >> "$XH_PINNED_KEY"
    fi
  done < "$XH_KEYSCAN"

  sort -u "$XH_PINNED_KEY" -o "$XH_PINNED_KEY"
  test "$(wc -l < "$XH_PINNED_KEY")" -eq 1
  echo 'SFTP host key: OK'

Если REG.RU не сообщает fingerprint в панели или справке, запросить его у
поддержки. Не вводить пароль, пока проверенная строка не напечатала
`SFTP host key: OK`.

Один раз проверить вход через уже выбранный key:

  sftp -F /dev/null -P "$SFTP_PORT" \
    -o "UserKnownHostsFile=$XH_PINNED_KEY" \
    -o GlobalKnownHostsFile=/dev/null \
    -o StrictHostKeyChecking=yes \
    -o UpdateHostKeys=no \
    -o VerifyHostKeyDNS=no \
    -o ConnectTimeout=15 \
    -o ConnectionAttempts=1 \
    -o NumberOfPasswordPrompts=1 \
    -o PreferredAuthentications=password \
    -o PasswordAuthentication=yes \
    -o PubkeyAuthentication=no \
    -o KbdInteractiveAuthentication=no \
    -o ForwardAgent=no \
    -o ClearAllForwardings=yes \
    "$SFTP_USER@$SFTP_HOST"

В приглашении sftp выполнить; вместо DOCROOT вставить точный путь из ISPmanager:

  cd DOCROOT
  ls -la
  bye

После выхода удалить временные key-файлы:

  rm -f -- "$XH_KEYSCAN" "$XH_ONE_KEY" "$XH_PINNED_KEY"
  trap - EXIT

В проверенном аккаунте REG.RU для SFTP подошёл пароль учётной записи панели, а
не отдельный FTP-пароль. Если в панели указан отдельный SSH/SFTP-пароль,
использовать его. После одной ошибки проверить выбранный логин и пароль, а не
перебирать варианты.

Отсутствие .htaccess на новом сайте нормально. Не создавать пустой файл.


7. Закрыть BACKEND_PORT на exit
================================

Этот раздел выполняется до запуска Xray в уже открытой SSH-сессии.
По запросу ввести измеренный FRONT_EGRESS_IP; BACKEND_PORT оставить 8083:

  read -r -p 'FRONT_EGRESS_IP: ' XH_FRONT_EGRESS_IP
  read -r -p 'BACKEND_PORT [8083]: ' XH_BACKEND_PORT
  XH_BACKEND_PORT="${XH_BACKEND_PORT:-8083}"

  (
    set -Eeuo pipefail
    test -n "${SSH_CONNECTION:-}" || {
      echo 'Нужна открытая SSH-сессия'; exit 1;
    }

    read -r XH_SSH_CLIENT_IP XH_SSH_CLIENT_PORT \
      XH_SSH_SERVER_IP XH_SSH_LISTEN_PORT <<< "$SSH_CONNECTION"

    python3 -c 'import ipaddress,sys; f=ipaddress.ip_address(sys.argv[1]); p=[int(x) for x in sys.argv[2:]]; (f.version == 4 and f.is_global) or sys.exit("FRONT_EGRESS_IP не публичный IPv4"); all(1 <= x <= 65535 for x in p) or sys.exit("Некорректный порт"); p[0] != p[1] or sys.exit("BACKEND_PORT совпадает с SSH-портом")' \
      "$XH_FRONT_EGRESS_IP" "$XH_SSH_LISTEN_PORT" "$XH_BACKEND_PORT"

    sudo /usr/sbin/sshd -T \
      | awk '$1 == "port" { print $2 }' \
      | grep -Fx -- "$XH_SSH_LISTEN_PORT" >/dev/null
    sudo ss -H -lntp "sport = :$XH_SSH_LISTEN_PORT" | grep sshd >/dev/null

    sudo apt-get update
    sudo apt-get install -y ufw

    sudo env LC_ALL=C ufw status verbose
    XH_UFW_ADDED="$(sudo env LC_ALL=C ufw show added)"
    printf '%s\n' "$XH_UFW_ADDED"
    sudo env LC_ALL=C ufw status | grep -Fx 'Status: inactive' >/dev/null
    if printf '%s\n' "$XH_UFW_ADDED" | grep '^ufw ' >/dev/null; then
      echo 'UFW уже содержит правила; остановиться'; exit 1
    fi

    XH_NFT_RULESET=''
    if command -v nft >/dev/null 2>&1; then
      XH_NFT_RULESET="$(sudo nft list ruleset)"
    fi
    XH_IPT_RULESET="$(sudo iptables-save)"
    XH_IP6T_RULESET="$(sudo ip6tables-save)"
    if printf '%s\n' "$XH_NFT_RULESET" \
      | grep -E 'hook (input|forward|output)' >/dev/null; then
      printf '%s\n' "$XH_NFT_RULESET"
      echo 'Есть чужой nftables ruleset; остановиться'; exit 1
    fi
    if printf '%s\n' "$XH_IPT_RULESET" "$XH_IP6T_RULESET" \
      | grep -E '^(-A |:[^[:space:]]+[[:space:]]+(-|DROP|REJECT)[[:space:]])' \
        >/dev/null; then
      printf '%s\n' "$XH_IPT_RULESET" "$XH_IP6T_RULESET"
      echo 'Есть чужие iptables rules; остановиться'; exit 1
    fi
    if command -v docker >/dev/null 2>&1 \
      || sudo systemctl is-active --quiet docker.service; then
      echo 'На exit есть Docker; этот UFW-блок не применять'; exit 1
    fi

    sudo ufw default deny incoming
    sudo ufw default allow outgoing
    sudo ufw allow "$XH_SSH_LISTEN_PORT/tcp" comment 'ssh current session'
    sudo ufw insert 1 allow from "$XH_FRONT_EGRESS_IP/32" \
      to any port "$XH_BACKEND_PORT" proto tcp comment 'xhttp frontend'
    sudo ufw insert 2 deny to any port "$XH_BACKEND_PORT" proto tcp \
      comment 'xhttp backend deny'
    sudo ufw --force enable
    sudo env LC_ALL=C ufw status verbose
    sudo env LC_ALL=C ufw status numbered
  )

В выводе должны быть:

  - allow SSH на фактическом EXIT_SSH_PORT;
  - allow BACKEND_PORT только от FRONT_EGRESS_IP;
  - deny BACKEND_PORT для остальных адресов;
  - allow расположен выше deny;
  - нет общего ALLOW BACKEND_PORT Anywhere.

Не закрывая текущую сессию, с обычного Linux/WSL войти на exit ещё раз той
же SSH-командой, которой открывалась первая сессия. Во второй сессии выполнить:

  sudo env LC_ALL=C ufw status numbered

Если второй вход не удался, в первой сессии выполнить `sudo ufw disable`,
исправить правила и Xray не запускать. Если у VPS есть cloud firewall, оставить в нём
SSH от адресов управления и BACKEND_PORT только от FRONT_EGRESS_IP/32.
После успешной проверки вернуться в первую SSH-сессию и выполнять раздел 8
именно в ней: там сохранены XH_FRONT_EGRESS_IP и XH_BACKEND_PORT.

    : "${XH_FRONT_EGRESS_IP:?выполнять в первой SSH-сессии из раздела 7}"
    : "${XH_BACKEND_PORT:?выполнять в первой SSH-сессии из раздела 7}"

Файл firewall-plan.txt не запускать через bash, source или eval. Он нужен только

На российском bridge проверить, что прямой доступ к backend закрыт:

  (
    set -Eeuo pipefail
    read -r -p 'EXIT_IP: ' EXIT_IP
    BACKEND_PORT='8083'
    command -v bash >/dev/null
    command -v timeout >/dev/null
    python3 -c 'import ipaddress,sys; v=ipaddress.ip_address(sys.argv[1]); (v.version == 4 and v.is_global) or sys.exit("EXIT_IP не публичный IPv4")' \
      "$EXIT_IP"

    set +e
    timeout 5 bash -c \
      "exec 3<>/dev/tcp/$EXIT_IP/$BACKEND_PORT" 2>/dev/null
    XH_PROBE_RC=$?
    set -e
    case "$XH_PROBE_RC" in
      0) echo 'ОШИБКА: backend доступен напрямую'; exit 1 ;;
      1|124) echo 'OK: backend закрыт от bridge' ;;
      *) echo "Ошибка прямой проверки backend, rc=$XH_PROBE_RC"; exit 1 ;;
    esac
  )

Если показана ошибка, не переходить к frontend и не вводить подтверждение
firewall.


9. Перенести handoff.json на российский bridge
================================================

В веб-консоли каждого VPS выполнить:

  ssh-keygen -E sha256 -lf /etc/ssh/ssh_host_ed25519_key.pub

Записать отдельно EXIT_HOSTKEY_SHA256 и BRIDGE_HOSTKEY_SHA256. Команда ниже
запускается из Bash на обычном Linux/WSL. Она закрепляет оба ключа, сверяет три
копии и не печатает JSON. Вводить пароли exit и bridge только в штатные SSH/SCP
запросы:

  (
    set -Eeuo pipefail
    umask 077

    read -r -p 'EXIT_IP: ' EXIT_IP
    read -r -p 'EXIT_SSH_PORT: ' EXIT_SSH_PORT
    read -r -p 'EXIT_HOSTKEY_SHA256: ' EXIT_HOSTKEY_SHA256
    read -r -p 'BRIDGE_IP: ' BRIDGE_IP
    read -r -p 'BRIDGE_SSH_PORT: ' BRIDGE_SSH_PORT
    read -r -p 'BRIDGE_HOSTKEY_SHA256: ' BRIDGE_HOSTKEY_SHA256

    XH_STATE="$HOME/.local/state/xhttp-setup"
    XH_TMP="$(mktemp -d)"
    trap 'rm -rf -- "$XH_TMP"' EXIT

    if test -e "$XH_STATE" || test -L "$XH_STATE"; then
      test -d "$XH_STATE" && test ! -L "$XH_STATE"
      test "$(stat -c '%a %u' "$XH_STATE")" = "700 $(id -u)"
    else
      install -d -m 700 "$XH_STATE"
    fi

    xh_pin_host() {
      local XH_HOST="$1" XH_PORT="$2" XH_EXPECTED="${3%=}"
      local XH_OUTPUT="$4" XH_SCAN XH_MATCH XH_LINE XH_FP XH_COUNT
      XH_SCAN="$(mktemp "$XH_TMP/scan.XXXXXX")"
      XH_MATCH="$(mktemp "$XH_TMP/match.XXXXXX")"
      chmod 600 "$XH_SCAN" "$XH_MATCH"
      [[ "$XH_EXPECTED" =~ ^SHA256:[A-Za-z0-9+/]{43}$ ]]
      ssh-keyscan -T 10 -p "$XH_PORT" -t ed25519,ecdsa,rsa \
        "$XH_HOST" > "$XH_SCAN" 2>/dev/null
      test -s "$XH_SCAN"
      : > "$XH_MATCH"
      XH_COUNT=0
      while IFS= read -r XH_LINE; do
        test -n "$XH_LINE" || continue
        case "$XH_LINE" in \#*) continue ;; esac
        XH_FP="$(printf '%s\n' "$XH_LINE" \
          | ssh-keygen -E sha256 -lf - | awk 'NR == 1 {print $2}')"
        XH_FP="${XH_FP%=}"
        if test "$XH_FP" = "$XH_EXPECTED"; then
          printf '%s\n' "$XH_LINE" >> "$XH_MATCH"
          XH_COUNT=$((XH_COUNT + 1))
        fi
      done < "$XH_SCAN"
      sort -u "$XH_MATCH" -o "$XH_MATCH"
      XH_COUNT="$(wc -l < "$XH_MATCH")"
      test "$XH_COUNT" -eq 1
      if test -e "$XH_OUTPUT" || test -L "$XH_OUTPUT"; then
        test -f "$XH_OUTPUT" && test ! -L "$XH_OUTPUT"
        test "$(stat -c '%a %u' "$XH_OUTPUT")" = "600 $(id -u)"
        cmp -s "$XH_MATCH" "$XH_OUTPUT"
      else
        install -m 600 "$XH_MATCH" "$XH_OUTPUT"
      fi
    }

    XH_EXIT_KH="$XH_STATE/exit.known_hosts"
    XH_BRIDGE_KH="$XH_STATE/bridge.known_hosts"
    xh_pin_host "$EXIT_IP" "$EXIT_SSH_PORT" \
      "$EXIT_HOSTKEY_SHA256" "$XH_EXIT_KH"
    xh_pin_host "$BRIDGE_IP" "$BRIDGE_SSH_PORT" \
      "$BRIDGE_HOSTKEY_SHA256" "$XH_BRIDGE_KH"

    XH_SSH_OPTS=(
      -F /dev/null
      -o GlobalKnownHostsFile=/dev/null
      -o StrictHostKeyChecking=yes
      -o UpdateHostKeys=no
      -o VerifyHostKeyDNS=no
      -o ConnectTimeout=15
      -o ConnectionAttempts=1
      -o NumberOfPasswordPrompts=1
      -o PreferredAuthentications=password
      -o PasswordAuthentication=yes
      -o PubkeyAuthentication=no
      -o KbdInteractiveAuthentication=no
      -o ForwardAgent=no
      -o ClearAllForwardings=yes
      -o RequestTTY=no
    )

    xh_exit_ssh() {
      ssh "${XH_SSH_OPTS[@]}" -o "UserKnownHostsFile=$XH_EXIT_KH" \
        -p "$EXIT_SSH_PORT" "root@$EXIT_IP" "$@"
    }
    xh_bridge_ssh() {
      ssh "${XH_SSH_OPTS[@]}" -o "UserKnownHostsFile=$XH_BRIDGE_KH" \
        -p "$BRIDGE_SSH_PORT" "root@$BRIDGE_IP" "$@"
    }
    xh_exit_hash() {
      xh_exit_ssh 'set -eu
        p=/var/lib/xhttp-setup/handoff.json
        test -f "$p" && test ! -L "$p"
        test "$(stat -c "%a %u:%g" "$p")" = "600 0:0"
        sha256sum "$p" | awk "{print \$1}"'
    }
    xh_require_hash() {
      [[ "$1" =~ ^[0-9a-f]{64}$ ]]
    }

    XH_EXIT_HASH_BEFORE="$(xh_exit_hash)"
    xh_require_hash "$XH_EXIT_HASH_BEFORE"

    XH_LOCAL="$XH_TMP/handoff.json"
    scp "${XH_SSH_OPTS[@]}" -o "UserKnownHostsFile=$XH_EXIT_KH" \
      -P "$EXIT_SSH_PORT" \
      "root@$EXIT_IP:/var/lib/xhttp-setup/handoff.json" "$XH_LOCAL"
    chmod 600 "$XH_LOCAL"
    XH_LOCAL_HASH="$(sha256sum "$XH_LOCAL" | awk '{print $1}')"
    xh_require_hash "$XH_LOCAL_HASH"

    XH_EXIT_HASH_AFTER="$(xh_exit_hash)"
    xh_require_hash "$XH_EXIT_HASH_AFTER"
    test "$XH_EXIT_HASH_BEFORE" = "$XH_EXIT_HASH_AFTER"
    test "$XH_EXIT_HASH_AFTER" = "$XH_LOCAL_HASH"

    XH_BRIDGE_EXISTING_HASH="$(xh_bridge_ssh 'set -eu
      d=/root/xhttp-live
      if test -e "$d" || test -L "$d"; then
        test -d "$d" && test ! -L "$d"
        test "$(stat -c "%a %u:%g" "$d")" = "700 0:0"
      else
        install -d -o root -g root -m 700 "$d"
      fi
      u=$d/handoff.json.upload
      if test -e "$u" || test -L "$u"; then
        test -f "$u" && test ! -L "$u"
        test "$(stat -c "%a %u:%g" "$u")" = "600 0:0"
        rm -f "$u"
      fi
      p=$d/handoff.json
      if test -e "$p" || test -L "$p"; then
        test -f "$p" && test ! -L "$p"
        test "$(stat -c "%a %u:%g" "$p")" = "600 0:0"
        sha256sum "$p" | awk "{print \$1}"
      else
        printf "%s\n" ABSENT
      fi')"

    if test "$XH_BRIDGE_EXISTING_HASH" = ABSENT; then
      scp "${XH_SSH_OPTS[@]}" -o "UserKnownHostsFile=$XH_BRIDGE_KH" \
        -P "$BRIDGE_SSH_PORT" "$XH_LOCAL" \
        "root@$BRIDGE_IP:/root/xhttp-live/handoff.json.upload"

      XH_BRIDGE_STAGE_HASH="$(xh_bridge_ssh 'set -eu
        u=/root/xhttp-live/handoff.json.upload
        test -f "$u" && test ! -L "$u"
        chown root:root "$u" && chmod 600 "$u"
        test "$(stat -c "%a %u:%g" "$u")" = "600 0:0"
        sha256sum "$u" | awk "{print \$1}"')"
      xh_require_hash "$XH_BRIDGE_STAGE_HASH"
      test "$XH_BRIDGE_STAGE_HASH" = "$XH_LOCAL_HASH"

      XH_BRIDGE_HASH="$(xh_bridge_ssh "set -eu
        expected=$XH_LOCAL_HASH
        d=/root/xhttp-live
        u=\$d/handoff.json.upload
        p=\$d/handoff.json
        test -f \"\$u\" && test ! -L \"\$u\"
        test \"\$(stat -c '%a %u:%g' \"\$u\")\" = '600 0:0'
        h_before=\$(sha256sum \"\$u\" | awk '{print \$1}')
        test \"\$h_before\" = \"\$expected\"
        test ! -e \"\$p\" && test ! -L \"\$p\"
        mv -T -n \"\$u\" \"\$p\"
        test ! -e \"\$u\"
        test -f \"\$p\" && test ! -L \"\$p\"
        test \"\$(stat -c '%a %u:%g' \"\$p\")\" = '600 0:0'
        h_after=\$(sha256sum \"\$p\" | awk '{print \$1}')
        test \"\$h_after\" = \"\$expected\"
        printf '%s\n' \"\$h_after\"")"
    else
      xh_require_hash "$XH_BRIDGE_EXISTING_HASH"
      XH_BRIDGE_HASH="$XH_BRIDGE_EXISTING_HASH"
    fi
    xh_require_hash "$XH_BRIDGE_HASH"
    test "$XH_BRIDGE_HASH" = "$XH_LOCAL_HASH"

    echo 'handoff transfer: OK'
  )

Не открывать и не печатать handoff.json. В нём находятся UUID и VLESS Encryption
material. Копии на exit и bridge оставить с правами 0600.

11. Забрать и проверить client.vless
====================================

Блок ниже запускать на той же Linux/WSL-машине и от того же пользователя, что и
раздел 9: он использует сохранённый `bridge.known_hosts`. Файл попадёт в отдельный
каталог Linux с правами 0700, а не в текущий каталог или `/mnt/c`.

  (
    set -Eeuo pipefail
    umask 077
    read -r -p 'BRIDGE_IP: ' BRIDGE_IP
    read -r -p 'BRIDGE_SSH_PORT: ' BRIDGE_SSH_PORT
    read -r -p 'FRONT_DOMAIN: ' FRONT_DOMAIN
    [[ "$FRONT_DOMAIN" =~ ^[a-z0-9]([a-z0-9.-]*[a-z0-9])?$ ]]
    [[ "$FRONT_DOMAIN" != *..* ]]
    XH_BRIDGE_KH="$HOME/.local/state/xhttp-setup/bridge.known_hosts"
    test -f "$XH_BRIDGE_KH" && test ! -L "$XH_BRIDGE_KH"
    test "$(stat -c '%a %u' "$XH_BRIDGE_KH")" = "600 $(id -u)"

    XH_SSH_OPTS=(
      -F /dev/null
      -o "UserKnownHostsFile=$XH_BRIDGE_KH"
      -o GlobalKnownHostsFile=/dev/null
      -o StrictHostKeyChecking=yes
      -o UpdateHostKeys=no
      -o VerifyHostKeyDNS=no
      -o ConnectTimeout=15
      -o ConnectionAttempts=1
      -o NumberOfPasswordPrompts=1
      -o PreferredAuthentications=password
      -o PasswordAuthentication=yes
      -o PubkeyAuthentication=no
      -o KbdInteractiveAuthentication=no
      -o ForwardAgent=no
      -o ClearAllForwardings=yes
      -o RequestTTY=no
    )
    xh_bridge_hash() {
      ssh "${XH_SSH_OPTS[@]}" -p "$BRIDGE_SSH_PORT" \
        "root@$BRIDGE_IP" "set -eu
          p=/var/lib/xhttp-setup/fronts/$FRONT_DOMAIN/client.vless
          test -f \"\$p\" && test ! -L \"\$p\"
          test \"\$(stat -c '%a %u:%g' \"\$p\")\" = '600 0:0'
          test -s \"\$p\"
          sha256sum \"\$p\" | awk '{print \$1}'"
    }
    xh_require_hash() {
      [[ "$1" =~ ^[0-9a-f]{64}$ ]]
    }

    XH_REMOTE_HASH_BEFORE="$(xh_bridge_hash)"
    xh_require_hash "$XH_REMOTE_HASH_BEFORE"

    XH_CLIENT_DIR="$HOME/.local/state/xhttp-setup/client-links/$FRONT_DOMAIN"
    if test -e "$XH_CLIENT_DIR" || test -L "$XH_CLIENT_DIR"; then
      test -d "$XH_CLIENT_DIR" && test ! -L "$XH_CLIENT_DIR"
      test "$(stat -c '%a %u' "$XH_CLIENT_DIR")" = "700 $(id -u)"
    else
      install -d -m 700 "$XH_CLIENT_DIR"
    fi
    XH_CLIENT_FILE="$XH_CLIENT_DIR/client.vless"

    if test -e "$XH_CLIENT_FILE" || test -L "$XH_CLIENT_FILE"; then
      test -f "$XH_CLIENT_FILE" && test ! -L "$XH_CLIENT_FILE"
      test "$(stat -c '%a %u' "$XH_CLIENT_FILE")" = "600 $(id -u)"
      XH_LOCAL_HASH="$(sha256sum "$XH_CLIENT_FILE" | awk '{print $1}')"
      xh_require_hash "$XH_LOCAL_HASH"
      XH_REMOTE_HASH_AFTER="$(xh_bridge_hash)"
      xh_require_hash "$XH_REMOTE_HASH_AFTER"
      test "$XH_REMOTE_HASH_BEFORE" = "$XH_REMOTE_HASH_AFTER"
      test "$XH_REMOTE_HASH_AFTER" = "$XH_LOCAL_HASH"
    else
      XH_STAGE="$(mktemp "$XH_CLIENT_DIR/.client.vless.upload.XXXXXX")"
      trap 'rm -f -- "$XH_STAGE"' EXIT
      chmod 600 "$XH_STAGE"
      scp "${XH_SSH_OPTS[@]}" -P "$BRIDGE_SSH_PORT" \
        "root@$BRIDGE_IP:/var/lib/xhttp-setup/fronts/$FRONT_DOMAIN/client.vless" \
        "$XH_STAGE"
      chmod 600 "$XH_STAGE"
      test -f "$XH_STAGE" && test ! -L "$XH_STAGE" && test -s "$XH_STAGE"
      test "$(stat -c '%a %u' "$XH_STAGE")" = "600 $(id -u)"
      XH_LOCAL_HASH="$(sha256sum "$XH_STAGE" | awk '{print $1}')"
      xh_require_hash "$XH_LOCAL_HASH"
      XH_REMOTE_HASH_AFTER="$(xh_bridge_hash)"
      xh_require_hash "$XH_REMOTE_HASH_AFTER"
      test "$XH_REMOTE_HASH_BEFORE" = "$XH_REMOTE_HASH_AFTER"
      test "$XH_REMOTE_HASH_AFTER" = "$XH_LOCAL_HASH"
      test ! -e "$XH_CLIENT_FILE" && test ! -L "$XH_CLIENT_FILE"
      mv -T -n "$XH_STAGE" "$XH_CLIENT_FILE"
      test ! -e "$XH_STAGE"
      trap - EXIT
      test -f "$XH_CLIENT_FILE" && test ! -L "$XH_CLIENT_FILE"
      test "$(stat -c '%a %u' "$XH_CLIENT_FILE")" = "600 $(id -u)"
      test "$(sha256sum "$XH_CLIENT_FILE" | awk '{print $1}')" = "$XH_LOCAL_HASH"
    fi
    printf 'client.vless: OK: %s\n' "$XH_CLIENT_FILE"
  )

Не публиковать ссылку и не добавлять файл в GitHub.

После импорта профиль должен содержать:

  address       CLIENT_CONNECT_IP
  port          443
  type          xhttp
  security      tls
  sni           FRONT_DOMAIN
  host          FRONT_DOMAIN
  fp            edge
  pcs           TLS_PIN
  mode          packet-up
  path          случайный /api/... из handoff
  extra         scMaxEachPostBytes=1000000
  extra         scMinPostsIntervalMs=30
  encryption    не none
  allowInsecure отсутствует

Если в итоговом JSON клиента после импорта нет `pcs`, VLESS Encryption или обоих
параметров `extra`, этот импортёр для ссылки не подходит. Поля в окне профиля не заменяют
проверку JSON.

Включить профиль и открыть:

  https://www.cloudflare.com/cdn-cgi/trace

Строка ip= должна содержать EXIT_EGRESS_IP. Затем проверить соединение с той
SIM-карты и сети, для которой настраивалась схема. Технический E2E через REG.RU
не проверяет правила конкретного мобильного оператора на TCP 443.


12. Проверка после перезапуска
==============================

На exit:

  (
    set -Eeuo pipefail
    sudo systemctl restart xhttp-setup-xray
    sleep 2
    test "$(sudo systemctl is-active xhttp-setup-xray)" = active
    sudo /usr/local/bin/xhttp-setup doctor --scope exit
    sudo env LC_ALL=C ufw status | grep -Fx 'Status: active' >/dev/null
    sudo ufw status numbered
    echo 'restart: OK'
  )

После этого снова подключить клиент и проверить ip=EXIT_EGRESS_IP. Прямой тест
BACKEND_PORT с bridge должен по-прежнему показывать, что порт закрыт.


13. Если front завершился ошибкой
==================================

При первом запуске, когда `client.vless` до старта отсутствовал, ошибка не должна
оставить новый файл. На bridge проверить это так:

  (
    set -Eeuo pipefail
    read -r -p 'FRONT_DOMAIN: ' FRONT_DOMAIN
    [[ "$FRONT_DOMAIN" =~ ^[a-z0-9]([a-z0-9.-]*[a-z0-9])?$ ]]
    [[ "$FRONT_DOMAIN" != *..* ]]
    XH_FRONT_STATE="/var/lib/xhttp-setup/fronts/$FRONT_DOMAIN"
    if sudo test -e "$XH_FRONT_STATE/client.vless" \
      || sudo test -L "$XH_FRONT_STATE/client.vless"; then
      echo 'ОШИБКА: осталась непроверенная ссылка'; exit 1
    fi
    echo 'Непроверенной ссылки нет'
    if sudo test -f "$XH_FRONT_STATE/last-failure.log"; then
      sudo sed -n '1,160p' "$XH_FRONT_STATE/last-failure.log"
    else
      echo 'last-failure.log не создан: ошибка возникла до managed state'
    fi
  )

Дальше действовать по этапу ошибки:

  - SFTP/SSH-аутентификация: проверить SFTP_HOST, SFTP_USER, fingerprint и
    пароль; не перебирать пароли.
  - Несовпадение SHA-256 leaf: повторить раздел 4 с тем же CLIENT_CONNECT_IP
    и SNI; не включать allowInsecure.
  - Ошибка E2E: проверить service/Doctor/UFW на exit и DNS/TLS на frontend.
    Managed-файлы этого запуска откатываются.
  - `rollback неполон`: не повторять запуск и не удалять .xhttp-backup-*,
    quarantine или локальный backups, перечисленные в ошибке.

Отсутствующая .htaccess до первого запуска не является ошибкой. Программа сама
создаёт managed-файл и удаляет его при полном rollback.


14. Граница проверки
======================

Сквозной bare-Xray E2E через REG.RU, exact /32 UFW, restart Xray и
отрицательные проверки pin/UUID выполнены. Импорт в конкретный GUI-клиент,
доступ с целевой SIM и длительная нагрузка остаются проверками владельца.
Полный факт-лист: docs/reference-audit-2026-08-19.md.
