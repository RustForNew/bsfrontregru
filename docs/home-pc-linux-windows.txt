XHTTP-SETUP 0.4.0: ЗАПУСК С ДОМАШНЕГО ПК
=========================================

АРХИВНАЯ СПРАВКА ДЛЯ 0.4.0. Текущая единая пользовательская инструкция —
INSTRUCTION.txt из GitHub Release 0.4.1. Этот файл больше не входит в Release.

Один и тот же мастер настраивает exit, frontend REG.RU и выполняет сквозную
проверку. На серверы вручную устанавливать программу не нужно.

Пароли вводятся скрыто, не печатаются и не сохраняются. Не вставляйте реальные
пароли в командную строку, файл, issue или публичный чат.


1. Подготовить данные
====================

До запуска должны быть готовы:

  - блок exit из трёх строк: публичный IPv4, root, пароль;
  - полный блок REG.RU «Логины и пароли»;
  - FRONT_DOMAIN и SITE_IP подготовленного сайта;
  - CLIENT_CONNECT_IP и DNS_IPV4;
  - TLS_PIN для описанной схемы с самоподписанным сертификатом;
  - FRONT_EGRESS_IP, измеренный до установки;
  - независимые SSH/SFTP host-key fingerprints вида SHA256:...;
  - точный DOCROOT, если frontend настраивается через российский bridge;
  - при необходимости блок bridge: публичный IPv4, root, пароль.

Подготовка сайта, TLS_PIN, FRONT_EGRESS_IP, SFTP и DOCROOT описаны в:

  docs/reg-ru-ispmanager-setup.txt

Exit должен быть чистым Debian/Ubuntu с systemd, прямым root SSH и уже активным
UFW. Режим pc не подходит для exit с Docker/containerd, nftables.service,
собственными nftables/iptables или другими сервисами на backend-порту. Порт Xray
по умолчанию 8083 и не должен совпадать с SSH-портом.

Мастер намеренно не включает неактивный UFW и не меняет SSH/default policy: это
защита от потери доступа. Внешний cloud firewall провайдера он тоже не меняет;
если тот фильтрует входящие соединения, разрешите backend только от
FRONT_EGRESS_IP/32 к выбранному TCP-порту Xray.

Fingerprint каждого SSH/SFTP-узла получите независимо из панели/консоли
провайдера или у поддержки. Не копируйте как доверенный fingerprint результат
первого ssh-keyscan к неизвестному узлу.


2. Linux: скачать, проверить и запустить
========================================

Нужны Python 3.10+, curl, sha256sum и OpenSSH client. Для Debian/Ubuntu:

  sudo apt-get update
  sudo apt-get install -y python3 curl coreutils openssh-client

Скачайте оба Linux-файла релиза:

  ASSET='xhttp-setup-0.4.0.pyz'
  BASE='https://github.com/RustForNew/bsfrontregru/releases/download/v0.4.0'
  curl --fail --location --remote-name "$BASE/$ASSET"
  curl --fail --location --remote-name "$BASE/$ASSET.sha256"

Проверьте SHA-256. Результат должен быть «OK»:

  printf '%s  %s\n' "$(tr -d '\r\n' < "$ASSET.sha256")" "$ASSET" \
    | sha256sum --check -

Запустите:

  python3 "$ASSET" --version
  python3 "$ASSET" pc


3. Windows: один раз установить WSL2
====================================

Windows-пакет запускает тот же Linux-мастер внутри WSL2. Это встроенная в
Windows среда Linux, а не переустановка системы.

Нужна Windows 11 либо Windows 10 версии 2004 (build 19041) или новее.

1) Откройте PowerShell от администратора.
2) Выполните:

     wsl --install -d Ubuntu

3) Перезагрузите компьютер.
4) Откройте Ubuntu из меню «Пуск». При первом запуске придумайте локальные имя и
   пароль Ubuntu. Это не логин и не пароль exit/REG.RU.
5) В PowerShell проверьте столбец VERSION:

     wsl --list --verbose

   Для Ubuntu должно быть указано 2. Если указано 1, выполните:

     wsl --set-version Ubuntu 2

6) В окне Ubuntu установите зависимости:

     sudo apt-get update
     sudo apt-get install -y python3 curl coreutils openssh-client


4. Windows: скачать, проверить и запустить
==========================================

Скачайте со страницы релиза в одну папку:

  xhttp-setup-0.4.0-windows-wsl.zip
  xhttp-setup-0.4.0-windows-wsl.zip.sha256

  https://github.com/RustForNew/bsfrontregru/releases/tag/v0.4.0

В обычном PowerShell перейдите в папку загрузки и выполните:

  $Zip = 'xhttp-setup-0.4.0-windows-wsl.zip'
  $Expected = (Get-Content -LiteralPath "$Zip.sha256" -Raw).Trim()
  $Actual = (Get-FileHash -LiteralPath $Zip -Algorithm SHA256).Hash
  if ($Actual -ine $Expected) { throw 'SHA-256 не совпал' }
  Expand-Archive -LiteralPath $Zip -DestinationPath '.\xhttp-setup-0.4.0'

Откройте папку xhttp-setup-0.4.0 и дважды нажмите START-WINDOWS.cmd. Не вынимайте
отдельные файлы из распакованной папки: launcher повторно проверяет вложенный
.pyz и запускает его в WSL2.

Native Windows без WSL2 не поддерживается.

Официальная инструкция Microsoft по WSL2:
  https://learn.microsoft.com/en-us/windows/wsl/install


5. Как вставлять готовые блоки
==============================

Выберите предлагаемый по умолчанию импорт готовых блоков. Содержимое вводится
скрыто: после вставки терминал не покажет текст. В конце каждого блока на новой
строке вручную напечатайте:

  ГОТОВО

Дождитесь сообщения «Блок принят». Скрытый ввод защищает экран, но не очищает
буфер обмена. Сразу после принятия блока очистите текущий буфер: в Windows это
можно сделать в отдельном PowerShell командой `Set-Clipboard -Value ''`, а в
Linux — штатной командой среды рабочего стола или копированием безопасного
текста. Историю (`Win+V`) и облачную синхронизацию очистите отдельно.

На вопросы импорта отвечайте Enter, чтобы принять [Y/n]:

  Вставить готовый блок выхода (IPv4, root, password)? [Y/n]
  Вставить готовый блок «Логины и пароли» REG.RU? [Y/n]

Если выбран bridge, появится также:

  Вставить готовый блок российского bridge (IPv4, root, password)? [Y/n]

EXIT. До строки ГОТОВО должны быть ровно три непустые строки без подписей:

  203.0.113.10
  root
  EXAMPLE_EXIT_PASSWORD
  ГОТОВО

Первая строка — только публичный IPv4, не hostname. Вторая — ровно root. Точка
после слова password из описания формата не добавляется к реальному паролю.

REG.RU. Вставьте целиком исходный текст, который выдал провайдер, включая
заголовки и значения. Разделы панели и FTP обязательны; MySQL может
присутствовать, но не используется. Безопасный пример:

  Доступ в панель управления хостингом
  Логин:
  EXAMPLE_PANEL_USER
  Пароль:
  EXAMPLE_PANEL_PASSWORD
  Ваша панель управления:
  Ispmanager
  Адрес панели управления хостингом:
  https://vipNNN.hosting.reg.ru:1500/

  Доступ к FTP
  Логин:
  EXAMPLE_FTP_USER
  Пароль:
  EXAMPLE_FTP_PASSWORD
  IP-адрес сервера:
  192.0.2.30

  Доступ к MySQL
  ...
  ГОТОВО

Мастер извлекает HTTPS-адрес, логин и пароль панели, FTP-логин и поле «IP-адрес
сервера». FTP-пароль только подтверждает структуру исходного блока: его значение
не сохраняется и не используется. Раздел MySQL также не сохраняется. Никакого
автоматического перехода к FTP-паролю при ошибке SFTP нет.

В проверенном формате REG.RU поле «IP-адрес сервера» совпадало с IP сайта. Мастер
предлагает его только как значение по умолчанию для CLIENT_CONNECT_IP, а затем
предлагает CLIENT_CONNECT_IP для DNS_IPV4. Оба адреса строго проверяются по DNS и
TLS. Это значение никогда не становится FRONT_EGRESS_IP или SFTP_HOST.

Не удаляйте строку «Ваша панель управления: Ispmanager». Импорт принимает только
ISPmanager и официальный узел панели вида vip<цифры>.hosting.reg.ru; другой вид
панели или адрес будет отклонён без попытки входа.

BRIDGE. Если выбран российский bridge, его скрытый блок имеет тот же строгий
формат IPv4/root/password/ГОТОВО, что и exit. Bridge должен быть доверенным: во
время настройки root этого VPS увидит handoff и выполнит frontend/E2E. В рабочем
трафике bridge не участвует.


6. Что вводить в остальных полях
================================

Если в квадратных скобках показано правильное значение, нажмите Enter. Иначе
введите фактическое значение.

SSH port выхода [22]
  Фактический порт sshd на exit. Число в названии тарифа/VPS не является портом.

Проверенный SSH host-key fingerprint выхода SHA256
  Независимо полученный fingerprint exit, не пароль и не TLS_PIN.

Публичный IPv4 выхода [IPv4 из первой строки блока]
  Нажмите Enter. При импорте другое значение будет отклонено.

Ожидаемый исходящий IPv4 выхода [публичный IPv4 выхода]
  Адрес, который должен показать E2E. Обычно равен публичному IPv4; при NAT
  укажите реальный исходящий адрес.

Фактический исходящий IPv4 shared-hosting (не угадывать по A-записи)
  FRONT_EGRESS_IP из измерения. Не подставляйте SITE_IP, DNS IP или поле
  «IP-адрес сервера» из блока REG.RU.

Порт Xray [8083]
  Оставьте 8083, если он свободен и не совпадает с SSH-портом.

Случайный XHTTP path [случайное значение]
  Нажмите Enter. Не придумывайте короткий или известный путь.

TLS fingerprint клиента [edge]
  Нажмите Enter. Это профиль uTLS клиента, а не сертификат и не SSH fingerprint.

Название подключения [XHTTP TLS]
  Любое понятное локальное название профиля; можно нажать Enter.

Frontend доступен только с российского IP и нужен доверенный SSH bridge? [y/N]
  «нет» — домашний IP напрямую открывает панель/SFTP REG.RU;
  «да» — доступ возможен только с российского IP, будет запрошен блок bridge.

FQDN/SNI существующего сайта frontend
  FRONT_DOMAIN без https://, порта и пути, например front.example.org.

IPv4 подключения клиента (адрес в VLESS URI) [IP из блока REG.RU]
  CLIENT_CONNECT_IP. При импорте предложено поле «IP-адрес сервера» из блока.
  Нажмите Enter только если оно совпадает с SITE_IP в карточке сайта.

IPv4 в DNS A домена (для сайта и ACME) [CLIENT_CONNECT_IP]
  DNS_IPV4. Нажмите Enter только если DNS действительно содержит этот адрес.
  Мастер требует ровно одну совпадающую A-запись, отсутствие AAAA и проверяет
  TLS/SNI на CLIENT_CONNECT_IP. В bridge-режиме проверки выполняются с bridge.

Закрепить SHA-256 текущего leaf-сертификата вместо проверки публичным CA? [y/N]
  Для этой инструкции с самоподписанным сертификатом ответьте «да».
  При публичном действующем сертификате от доверенного CA можно ответить «нет».

SHA-256 текущего leaf-сертификата (64 hex)
  TLS_PIN, полученный с правильными CLIENT_CONNECT_IP и SNI. После перевыпуска
  сертификата старый pin использовать нельзя.

SFTP hostname/IP
  При импорте вопрос не задаётся: SFTP_HOST берётся из URL панели без https:// и
  :1500, например vipNNN.hosting.reg.ru. Поле «IP-адрес сервера» для этого не
  используется. Без импорта введите SFTP_HOST вручную.

SFTP port [22]
  При импорте вопрос не задаётся: используется 22. Без импорта нажмите Enter,
  если провайдер не сообщил другой SFTP-порт.

SFTP user
  При импорте вопрос не задаётся: используется логин панели, причём импорт
  отклоняется, если логины панели и FTP различаются. Без импорта введите
  проверенного основного пользователя хостинга.

Получить document root read-only запросом к ISPmanager API? [y/N]
  В прямом режиме можно ответить «да»: мастер использует импортированные данные
  панели только для чтения существующего сайта. Endpoint автоматически строится
  только из проверенного URL панели REG.RU. В bridge-режиме API-поиск не
  предлагается.

Document root из списка сайтов ISPmanager
  Если API-поиск не использован, введите точный DOCROOT. Не собирайте путь по
  шаблону и не указывайте родительскую папку другого сайта.

Проверенный SSH host-key fingerprint SHA256
  Независимый fingerprint именно SFTP_HOST от REG.RU/поддержки.

Заменить index.html на оригинальную нейтральную заглушку со ссылкой на RuFox? [y/N]
  Обычно «нет»: существующую главную страницу мастер сохранит.

SSH port bridge [22]
  Появляется только при выборе bridge. Введите фактический SSH-порт VPS.

Проверенный SSH host-key fingerprint bridge SHA256
  Независимо полученный fingerprint российского VPS.


7. Подтверждение и пароли
=========================

Проверьте показанный план. Для старта введите точно:

  APPLY PC

Импортированный пароль exit применяется только к закреплённому SSH-ключу узла.
То же относится к bridge.

В прямом режиме мастер задаст точный вопрос:

  Использовать импортированный пароль панели как SFTP password? [y/N]

В bridge-режиме вопрос будет таким:

  Передать импортированный пароль панели как SFTP password через bridge? [y/N]

По умолчанию ответ «нет»: пароль панели никогда не применяется автоматически.
Ответьте «да» только если SFTP-вход этим паролем подтверждён для вашего аккаунта.
В прямом режиме после «нет» мастер спросит:

  Frontend SFTP: использовать отдельный SSH-ключ вместо пароля? [Y/n]

Можно указать отдельный ключ или ответить «нет» и ввести проверенный SFTP-пароль.
Если выбран ключ, в поле `Путь к приватному ключу [~/.ssh/id_ed25519]` укажите
существующий отдельный ключ SFTP-пользователя.
В bridge-режиме после «нет» будет скрытый запрос:

  SFTP password frontend для одноразовой передачи через bridge:

FTP-пароль из блока не сохраняется, не подставляется и не перебирается.

Мастер сам подключится к exit, безопасно добавит свои UFW allow/deny, применит
существующий транзакционный установщик сервера, затем настроит frontend напрямую
или через bridge. Не закрывайте окно до завершения.


8. Успешный результат
=====================

Успех обязательно содержит сообщение об E2E-проверке и точный путь к
client.vless. Ссылка выдаётся только после запроса через локальный SOCKS и
совпадения внешнего IP с ожидаемым исходящим IPv4 exit.

Если E2E не пройден, клиентская ссылка не выдаётся. Не отключайте проверку TLS,
не открывайте backend всему интернету и не перебирайте пароли. Исправьте поле,
указанное в ошибке, затем повторите запуск.


9. Известная граница проверки
=============================

Для импорта, PC-компонентов и Windows-обёртки предусмотрены автоматические тесты.
Это не заменяет live-проверку: полный путь v0.4.0 на реальных exit, REG.RU и
Windows/WSL2 сквозным E2E в рамках выпуска не подтверждён.
